# Shared Brain contract

Human-authored notes outside `Agents/` are authoritative and read-only to agents, not to the human owner. Follow owner policies over agent-authored memory. Never edit owner notes, Home, or attachments; propose corrections with the source path instead. Browser editing is a human-authoring workflow: agents must not use editor endpoints, browser automation, or the editor-only helper to bypass owner-note restrictions. These are rule-level safeguards, not OS isolation: arbitrary shell or eval can bypass them.

Human review and workspace management are reserved for the owner. Agents must not use review, editor, delete, workspace-settings, or Trash-restore endpoints, browser automation, or human-only helpers to bypass owner-note restrictions or alter the human review ledger. Changing source status does not confer review or owner authority. Respect owner-configured workspace names, icons, and Work/Home grouping.

Retrieve relevant memory for each task with the shared-memory search tool or `axiom-memory search --cwd <directory> --query <task>`; read matching notes with `read --path <vault-relative-path>` and cite their source paths. Search covers global memory and the current project, selected by the longest matching configured root. Do not treat a different project's notes as current-project facts.

Save durable, useful facts only in `Agents/` using the shared-memory write tool or `axiom-memory write --path Agents/... --expected <revision|new>` with Markdown on stdin. Read the current revision first and resolve conflicts rather than overwriting another change. Include sources and the appropriate project scope; use `Agents/Memory/Projects/<project-id>/` for project findings and `Agents/Memory/General/` for global knowledge. Do not save transient task details as durable facts. Native direct file writes bypass conflict detection and recovery history; do not use them for memory edits.

Before creating a note, search the relevant workspace and update an existing finding when it already covers the subject. Use a descriptive, outcome-focused title and one clear subject per note. Record verifiable source paths/URLs and the relevant revision or date, plus explicit project scope. Use `kind: decision` only for an actual decision; source evidence can be a flat `source:` field or a Sources section. Record an explicit `supersedes:` path when replacing an agent finding and mark the obsolete agent note superseded with its current revision. Use `conflicts_with:` for a known unresolved conflict, not a guessed contradiction. Never silently replace owner guidance, automatically merge uncertain notes, or create a near-duplicate instead of linking existing knowledge.

Each workspace has a unique Lucide icon recorded in `Agents/Workspace icons.md`. Before the first agent note in an unassigned workspace, search unused canonical icons with `shared_memory_workspace_icons` or `axiom-memory workspace-icons --query <term>`, choose a semantically relevant unused slug, and pass `workspaceIcon` to the write tool or `--workspace-icon <slug>` to the CLI. The write assigns it; later notes may omit it. Global and unconfigured-project notes use the global and `__unmapped` workspaces respectively. Do not reassign existing icons through ordinary note writes.
